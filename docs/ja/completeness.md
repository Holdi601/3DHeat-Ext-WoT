# 完全性 {#completeness}

リプレイの中身は何も捨てられません。変換ツールが読んだものはテーブルとマッチドキュメントに入ります。それ以外のすべての項目は、サイドカー `<match>.messages.parquet` に丸ごと残されます。そして、マッチドキュメントの `selfCheck.completeness` は、項目の種類ごとに、それがどうなったかを数えます。これは、すべての 3DHeat 変換ツールに共通のルールです: [変換ツールはすべてを残す](https://holdi601.github.io/3DHeat/converters.html)。

![合成リプレイの自己チェック: 見られた、読まれた、残された、失われた項目](../assets/img/completeness.svg)

## 数え方 {#the-count}

項目の種類ごとに、`selfCheck.completeness.types` は次を示します:

| 数 | 意味 |
|---|---|
| `seen` | リプレイが持っている数 |
| `decoded` | 丸ごと読まれた数 |
| `partial` | 一部が読まれ、サイドカーに丸ごと残された数 |
| `raw` | サイドカーに丸ごと残されただけで、読まれなかった数 |
| `lost` | 失われた数。常に `0` |

種類はリプレイ自身のものです: `block 0`（ヘッダー）、`block 1`（結果）、`container sizes` と `deflate tail`（コンテナー自身のバイト）、`packet <type>`。エンティティへの呼び出しには `method <entity type>.<number>` と `property <entity type>.<number>`。エンティティの型は、それを作るパケットが与える番号です。`selfCheck.entities.roles` は、どれが録画しているプレイヤーのアバターで、どれが車両かを示します。誰も知らなかった種類は、その数とともに現れます。

## サイドカー {#the-sidecar}

| 列 | 内容 |
|---|---|
| `time` | リプレイの時計。テーブルと同じ |
| `type`、`name` | 項目の種類。変換ツールがそれを何と呼んでいるか、どこで読んでいるか |
| `entity` | それが属する車両またはアバター。テーブルの `entity` と同じ |
| `decoded` | そこから読まれた内容。JSON 形式 |
| `payload`、`text` | そのバイト、丸ごと。JSON のブロック、丸ごと |
| `entityType`、`packet`、`method` | 番号 |

行は、パケット、メソッド、エンティティ、時刻の順に並びます。

## 読み取った内容と、その確かめ方 {#what-is-read-and-how-it-was-checked}

- すべての位置の**ピッチとロール**: ピッチは、戦車が前進している間の、その戦車自身の進路の傾斜の逆符号です。同じ場所にあり、同じ向きの 2 つの戦車は同じロールを持ち、逆向きの 2 つの戦車は逆のロールを持ちます。
- **エンティティ** （`entities`）: それぞれがいつクライアントの視界に入り、いつ出たか。戦車は、出てから戻るまでの間、位置を持ちません。
- **ストリームのバージョン** （`streamVersion`）: ヘッダーのものと同じ。
- **録画しているプレイヤーの照準**（パケット 38）: 方向。サイドカーの `decoded`（`forward`）にあります。プレイヤーの射撃では、砲弾が飛んだ方向と 1 度の何分の一かの差です。

ほかに読まれたすべて（体力、命中、射撃、曳光弾、爆発、砲の角度、アリーナの更新、チャット、カメラのモード、クライアントのイベント、位置）は `partial` です。テーブルかマッチドキュメントに入り、サイドカーに丸ごと残されます。

**残されたが読まれていないもの**（`raw`）で、最も大きな種類: テーブルにない位置の更新（アバターのもの、戦車の死後のもの、名簿にないエンティティ）、パケット 26、28、29、31、36、50、54、57、頻繁に出る車両とアバターのプロパティのいくつか、読み手のないすべてのメソッドとプロパティ（モジュールのダメージ、クルー、消耗品を含む）、そしてエンティティの作成のプロパティ。

## 使えないもの {#not-available}

- サーバーが録画したクライアントに送らなかったもの: ほかのプレイヤーの照準、カメラ、入力、発見されていない敵。リプレイは、1 つのクライアントが知らされたことそのものです。
- エンティティの型、メソッド、プロパティの名前: それらはリプレイではなく、ゲームの定義ファイルにあります。番号は残されます。
- 砲の仰角を度で示すこと、そのほか、ゲームのファイルにある戦車自身のデータを必要とするもの。
