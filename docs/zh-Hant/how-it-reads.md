# 讀取回放的方式 {#how-it-reads-a-replay}

回放是由 JSON 區塊組成的標頭，加上遊戲的封包串流（格式說明見 [`heat3d_ext_wot/bigworld.py`](https://github.com/Holdi601/3DHeat-Ext-WoT/blob/main/heat3d_ext_wot/bigworld.py)）：

- 第一個區塊，未加密：地圖、客戶端版本、錄製玩家、伺服器設定，以及名單（`vehicles`：名稱、隊伍、坦克，以載具的 id 為鍵）。
- 第二個區塊，在錄製持續到結束時才有：結算畫面，即每輛載具的一行（射擊、命中、穿透、造成的傷害、承受的傷害、阻擋與助攻的傷害、偵察、經驗、銀幣、成就……）、錄製玩家對每個目標的詳細資料、帳號、比賽時長、勝方與結束原因；在某些模式中，這是唯一完整的名單（這些名單的標頭只列出自己的隊伍）。
- 封包串流：以 zlib 壓縮，並以遊戲所附金鑰進行 Blowfish 加密；讀取這些檔案的社群工具自 2013 年起就已公開此金鑰。

**位置**是引擎的位置更新：載具的 id、其位置與航向，以它們的形狀而非封包編號找到，因此改編號的更新不會讓表格變空。它們是錄製客戶端被告知的內容：自己的隊伍全程都有，敵人則只在被偵察到時（或在客戶端的範圍內）才有。從未被偵察到的載具沒有任何列。載具的列在它陣亡時停止。

**串流的其餘部分**——血量、射擊、曳光彈、爆炸、命中、砲管角度、戰場更新——是載具與客戶端化身的方法呼叫與屬性變更，其編號由遊戲的定義檔案決定，而這些檔案會隨更新而改變（1.12 與 2.4 的編號不同）。每一項都是依據其引數的形狀及彼此的關係找到的——見 [`heat3d_ext_wot/stream.py`](https://github.com/Holdi601/3DHeat-Ext-WoT/blob/main/heat3d_ext_wot/stream.py)——找到的編號記錄在對戰文件的 `decoded` 中。聊天、攝影機模式與客戶端自己的事件，則是各自獨立的封包。戰場更新與客戶端事件是 Python pickle；讀取器會把它們提到的每個類別都換成無害的替身，且不執行任何程式碼。

客戶端被告知的內容，對於自己的隊伍是完整的，對於敵人則是部分的：他們的射擊、命中與血量變化，只在他們處於範圍內時才會出現。

**戰鬥開始**是戰場更新表示戰鬥時段開始的時刻；若回放中沒有這項更新，則是任何載具第一次移動的時刻。

**陣亡：**時間取自戰場的擊殺訊息（1.x），否則取自結束該載具的血量變化，否則取自戰鬥開始加上結算中受害者的 `lifeTime`（整秒）。地點是受害者最後被看到的位置，前提是該時間在其陣亡前五秒之內；否則，在 2.x 客戶端上，使用結算所給的地點（x 與 z，無高度），且僅保留在對戰文件中。在結束前就停止的錄製沒有任何陣亡紀錄。

**未讀取的內容：**

- 偵察與小地圖：串流中沒有作為獨立事件的記錄。
- 以度為單位的砲管仰角：串流中有砲管極限之間的一個步距，而這些極限位於遊戲的載具檔案中。
- 模組損傷、組員傷害、消耗品與彈藥：攜帶這些資料的呼叫，無法單靠形狀在 1.12 與 2.4 之間區分。
- 超出實體與其類型之外的實體建立封包：它們一次包含進入客戶端視野的載具的每個屬性，順序只有定義檔案才知道（完整保存在附屬檔案中）。
- 靜態碰撞物（樹木、房屋）、錄製玩家自己的瞄準與物理封包。
- 戰鬥聊天指令的編號作為名稱：編號是遊戲的，且會改變；對戰文件會保留每個指令的引數，包括其鍵（若有的話，例如 `ATTACK_ENEMY`……）。
- 攻擊原因大於 5 的：只寫成數字。

## 讀取是如何核對的 {#how-the-reading-was-checked}

讀取已在 1.12 與 2.4 客戶端的公開回放上核對，每個數值都與回放中另一處給出的值比對：

- **位置：**每輛曾被看到的坦克，都有以每秒十個取樣的軌跡；速度維持在坦克能達到的範圍內；航向與行進方向相差約 0.02 弧度；若結算給出陣亡地點，這裡讀取的地點與之相差幾公尺以內。
- **錄製玩家：**在每個已核對的回放上，射擊與造成的傷害讀取值都與結算相同。
- **血量：**每輛坦克最後讀到的血量與結算相同；讀到的承受傷害從未超過結算。在 2.4 上，對於不在客戶端視野中的坦克，致命的一擊常常未被送出。
- **命中：**幾乎每一次命中，其傷害都等於該時刻的血量變化。
- **砲塔：**在射擊時，車體的航向加上砲塔偏航角，指向曳光彈飛行的方向，誤差約為 0.01 弧度（中位數）。
- **陣亡與戰鬥開始：**與結算及戰場所給的時間相差約一秒以內。

測試會以相同的格式建立回放，因此本儲存庫中沒有保存任何真實回放。

**未核對的：**1.12 之前的客戶端、主機與 Blitz 的回放（不同的遊戲）、Lesta 的 Mir Tankov（`.mtreplay`），以及隨機戰鬥與戰鬥類型 20 之外的模式。
