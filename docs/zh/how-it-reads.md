# 工具如何读取录像 {#how-it-reads-a-replay}

录像由一个 JSON 块组成的文件头，加上游戏的数据包流（格式说明见 [`heat3d_ext_wot/bigworld.py`](https://github.com/Holdi601/3DHeat-Ext-WoT/blob/main/heat3d_ext_wot/bigworld.py)）：

- 第一个块，未加密：地图、客户端版本、录像播放者、服务器设置，以及名单（`vehicles`：名称、队伍、坦克，以载具的 ID 为键）。
- 第二个块，在录像一直持续到结束时存在：结果界面，即每辆载具的一行（射击、命中、穿透、造成的伤害、受到的伤害、格挡和助攻的伤害、侦察、经验、银币、成就……），录像播放者针对每个目标的详细数据，账号，对局时长、获胜方和结束原因；在某些模式下，这是唯一完整的名单（这些列表的表头只列出己方队伍）。
- 数据包流，经过 zlib 压缩，并使用游戏内置的密钥进行 Blowfish 加密；自 2013 年以来，读取这些文件的社区工具就已公开了这一密钥。

**位置**是引擎的位置更新：载具的 ID、它的位置和朝向，通过其结构而不是数据包编号来识别，因此即使某次补丁对它们重新编号，表格也不会变空。它们反映的是录像客户端所被告知的内容：全程包括己方队伍，敌方则只在被发现时（或在客户端的范围内）出现。从未被发现的载具没有任何行。载具的行在其死亡时停止。

**数据包流的其余部分**，包括生命值、射击、曳光弹、爆炸、命中、炮的角度、竞技场更新，是载具以及客户端化身的方法调用和属性变化，其编号由游戏的定义文件给出，并会随补丁而变化（1.12 和 2.4 的编号不同）。每一项都通过其参数的结构及其相互关系来识别（见 [`heat3d_ext_wot/stream.py`](https://github.com/Holdi601/3DHeat-Ext-WoT/blob/main/heat3d_ext_wot/stream.py)），所找到的编号保存在对局文档的 `decoded` 中。聊天、相机模式和客户端自身的事件，则是各自独立的数据包。竞技场更新和客户端事件是 Python pickle；读取器会把它们所命名的每个类转换为无害的替身，并且不执行任何代码。

客户端所被告知的内容，对于其自身队伍是完整的，对于敌人则是部分的：他们在处于范围内时的射击、命中和生命值变化都会出现。

**战斗开始**是指竞技场更新表明战斗阶段开始的时刻；在没有这一更新的录像中，则为任何载具首次移动的时刻。

**死亡：** 时间取自竞技场的击杀消息（1.x），否则取结束该载具的生命值变化，再否则取战斗开始时间加上结果中受害者的 `lifeTime`（整秒）。位置取受害者最后一次被看到的地方，前提是该地点距其死亡不超过五秒；否则，对于 2.x 客户端，取结果中给出的位置（x 和 z，无高度），仅出现在对局文档中。在结束之前就停止的录像没有死亡记录。

**未读取的内容：**

- 侦察和小地图：它们不以独立事件的形式出现在数据包流中。
- 以度为单位的火炮仰角：数据包流在火炮的极限之间有一个步进，而极限值存在于游戏的载具文件中。
- 模块损伤、乘组伤势、消耗品和弹药：携带它们的调用无法仅凭结构在 1.12 和 2.4 之间加以区分。
- 实体创建数据包中，除实体及其类型之外的部分：它们一次性包含进入客户端视野的载具的每一个属性，其顺序只有定义文件才会给出（完整保存在附属文件中）。
- 静态碰撞（树木、房屋），以及录像播放者自己的瞄准和物理数据包。
- 战斗聊天命令的编号作为名称：编号属于游戏，且会变化；对局文档保留每个命令的参数，包括其键（如果有的话，例如 `ATTACK_ENEMY` 等）。
- 大于 5 的攻击原因：只以数字形式记录。

## 读取的核对方式 {#how-the-reading-was-checked}

读取过程已在 1.12 和 2.4 客户端的公开录像上进行核对，每个数值都与录像中给出的另一次数值进行比较：

- **位置：** 每辆曾被看到的坦克都有一条每秒十个采样的轨迹；速度保持在坦克能够达到的范围之内；航向与行进方向的差距在约 0.02 弧度之内；如果结果给出了某次死亡的地点，则这里读取的位置与之相差在几米之内。
- **录像播放者：** 在所有已核对的录像上，射击和造成的伤害的读取值都与结果中的数值相等。
- **生命值：** 每辆坦克最后一次读取的生命值，都等于结果中的数值；读取到的受到伤害从不超过结果中的数值。在 2.4 上，对于不在客户端视野中的坦克，其致命一击往往不会被发送。
- **命中：** 几乎每一次命中的伤害，都等于该时刻的生命值变化。
- **炮塔：** 在射击时，车体的航向加上炮塔的偏航，指向曳光弹飞行的方向，误差在约 0.01 弧度之内（中位数）。
- **死亡和战斗开始：** 与结果和竞技场所给出的时间相差在约一秒之内。

测试会以相同的布局生成录像，因此本仓库中不保存任何真实录像。

**未核对的内容：** 1.12 之前的客户端、主机版和闪击战录像（不同的游戏）、Lesta 的 Mir Tankov（`.mtreplay`），以及除随机对战和战斗类型 20 之外的其他模式。
