# リプレイの読み取り方 {#how-it-reads-a-replay}

リプレイは、JSON のブロックのヘッダーと、ゲームのパケットの流れでできています（フォーマットのメモは [`heat3d_ext_wot/bigworld.py`](https://github.com/Holdi601/3DHeat-Ext-WoT/blob/main/heat3d_ext_wot/bigworld.py) にあります）:

- 最初のブロックは、暗号化されていない状態で入っています: マップ、クライアントのバージョン、録画しているプレイヤー、サーバーの設定、そして名簿（`vehicles`: 名前、チーム、戦車。車両の ID で示されます）。
- 2 つ目は、録画が最後まで続いた場合にあります: 結果の画面。すべての車両の行（射撃、命中、貫通、与えたダメージ、受けたダメージ、防いだダメージとアシスト、発見、経験値、クレジット、実績など）、録画しているプレイヤーの目標ごとの詳細、アカウント、戦闘の時間、勝者、終了の理由です。一部のモードでは、これが唯一の完全な名簿です（それらのリストのヘッダーには、自分のチームだけが並びます）。
- パケットの流れ。zlib で圧縮され、ゲームが持つ鍵で Blowfish で暗号化されています。この鍵は、これらのファイルを読むコミュニティのツールが 2013 年以来公開しています。

**位置**は、エンジンの位置の更新です。車両の ID、位置、方位を持ちます。パケットの番号ではなく、その形で見つけるので、番号を振り直すパッチがあってもテーブルは空になりません。これらは、録画したクライアントに知らされたものです。自分のチームは最初から最後まで、敵は発見されている間だけ（またはクライアントの範囲内にいる間）。一度も発見されなかった車両の行はありません。車両の行は、その破壊で止まります。

**ストリームの残り**（体力、射撃、曳光弾、爆発、命中、砲の角度、アリーナの更新）は、車両と、クライアントのアバターのメソッド呼び出しとプロパティの変更です。番号はゲームの定義ファイルによるもので、パッチによって変わります（1.12 と 2.4 では番号が違います）。それぞれは、引数の形と、それらがどうつながっているかで見つけられます。[`heat3d_ext_wot/stream.py`](https://github.com/Holdi601/3DHeat-Ext-WoT/blob/main/heat3d_ext_wot/stream.py) を参照してください。見つかった番号は、マッチドキュメントの `decoded` にあります。チャット、カメラのモード、クライアント自身のイベントは、それぞれ独自のパケットです。アリーナの更新とクライアントのイベントは Python の pickle です。それらは、名指しされたクラスを中身のないスタンドインに変えて、何も実行しない読み手で読まれます。

クライアントに知らされたことは、自分のチームについては完全で、敵については部分的です。敵の射撃、命中、体力の変化は、敵が範囲内にいた間は含まれています。

**戦闘の開始**は、アリーナの更新が戦闘の期間の始まりを示した時刻です。それがないリプレイでは、どの車両かが最初に動いた瞬間です。

**死亡:** 時刻は、アリーナのキルのメッセージ（1.x）、なければ車両を終わらせた体力の変化、なければ戦闘の開始に、結果から得た犠牲者の `lifeTime`（整数秒）を足したものです。場所は、犠牲者が最後に見られた場所です。死亡の 5 秒以内に見られていた場合に限ります。そうでなければ、2.x のクライアントでは、結果が示す場所（x と z のみ、高さなし）を使い、マッチドキュメントの中だけに入ります。終わる前に止まった録画には、死亡はありません。

**読まないもの:**

- 発見とミニマップ: それ自体のイベントとしてはストリームにありません。
- 砲の仰角を度で: ストリームには砲の限界の間の段階がありますが、その限界はゲームの車両ファイルにあります。
- モジュールのダメージ、クルーの負傷、消耗品、弾薬: それらを運ぶ呼び出しは、1.12 と 2.4 にわたって、形だけでは区別できませんでした。
- 車両とその型以外のエンティティ作成のパケット: それらは、クライアントの視界に入る車両のすべてのプロパティを一度に持っています。その順番は定義ファイルでしかわかりません（サイドカーに丸ごと残されます）。
- 静的な衝突（木、家）、録画しているプレイヤー自身の照準と物理のパケット。
- バトルチャットのコマンドの番号を名前として: 番号はゲームのもので、変わります。マッチドキュメントには、各コマンドの引数が残されます。そのなかには、キーがあればそのキー（`ATTACK_ENEMY` など）も含まれます。
- 5 を超える攻撃の理由: 番号だけで書かれます。

## 読み取りをどう確かめたか {#how-the-reading-was-checked}

読み取りは、クライアント 1.12 と 2.4 の公開されたリプレイで確かめました。各値は、リプレイがもう一度別に与えているものと比べています:

- **位置:** それまで見られたすべての戦車には、1 秒に 10 サンプルの航跡があります。速さは戦車ができる範囲に収まります。方位は進行方向と約 0.02 ラジアン以内で一致します。結果が死亡の場所を示している場合、ここで読んだ場所はそこから数 m 以内です。
- **録画しているプレイヤー:** 確かめたすべてのリプレイで、射撃と与えたダメージは、結果の値と等しく読まれます。
- **体力:** 各戦車の最後に読んだ体力は、結果と等しい。受けたダメージの読みは、結果より多くなることはありません。2.4 では、クライアントの視界の外の戦車へのとどめの一撃は、送られないことがよくあります。
- **命中:** 命中のダメージは、ほぼすべての命中で、その瞬間の体力の変化と等しい。
- **砲塔:** 射撃の時点で、車体の方位と砲塔の旋回角を足すと、曳光弾が飛んだ方向を、約 0.01 ラジアン以内（中央値）で指します。
- **死亡と戦闘の開始:** 結果とアリーナが示すことから、約 1 秒以内。

テストは、同じ形式でリプレイを作るので、このリポジトリには実際のリプレイは残されていません。

**確認していないもの:** 1.12 より前のクライアント、コンソール版やブリッツ版のリプレイ（別のゲーム）、Lesta の Mir Tankov（`.mtreplay`）、そしてランダム戦とバトルタイプ 20 以外のモード。
